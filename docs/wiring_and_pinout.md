# Wiring and pin-out: ESP32 DevKit V1 (30-pin)

* **Circuit diagram:** `docs/Circuit_Diagram.pdf` (schematic, wire-by-wire list, charging and safety)
  and `hardware/wiring_diagram.svg` / `.png`, all generated by `tools/make_wiring_diagram.py`
* **Authoritative pin table:** `hardware/pin_mapping.csv`
* **Firmware:** `firmware/src/hal_esp32/pins.h`

`simulator/tests/test_consistency.py` fails if `pins.h` and the CSV disagree, if a pin is used
twice, or if a flash, strapping or input-only pin is misused. The diagram reads its GPIO numbers from
the CSV, so it cannot drift either. Every pin used also exists on the 38-pin DevKitC.

## Pin table
| GPIO (board label) | Function | Connects to | Why this pin |
|---|---|---|---|
| 36 (VP), 39 (VN), 34, 35, 32 | IR array D1-D5 (D1 = robot's left) | 5-ch array D1-D5 | ADC1; 34-39 are input-only (fine for sensors) |
| 33 | left wing IR | left FC-51 OUT | ADC1 |
| 25 | right wing IR | right FC-51 OUT | ADC2, usable because Wi-Fi is never started |
| 26 | battery sense (optional) | VBAT -47k- GPIO26 -10k- GND | not fitted by default; build with `MESH_VBAT_SENSE=1` |
| 23 | left motor PWM | L298N ENA (jumper cap removed) | LEDC PWM, 1 kHz in the `esp32_l298n` build |
| 19, 18 | left motor direction | L298N IN1, IN2 | |
| 14 | right motor PWM | L298N ENB (jumper cap removed) | toggles at boot: a short motor twitch at power-on is possible |
| 5, 4 | right motor direction | L298N IN3, IN4 | GPIO5 is a strapping pin that only affects SDIO timing |
| 21, 22 | I2C SDA, SCL | MPU6050 SDA, SCL | ESP32 default I2C pins |
| 16, 17 | optional slot encoders L, R | LM393 slot sensors (not fitted) | interrupt inputs; `encoder_mode = 1` when fitted |
| 0 | START | on-board BOOT button | already has a pull-up; do not hold it at power-on |
| 15 | red end-zone LED | LED + (long leg); LED − to GND | 330 Ω in series recommended; firmware sets the weakest pin drive |
| 2 | status LED | on-board blue LED | strapping pin; the LED to GND is fine |
| 13 | (TB6612 STBY) | not connected | only used with the TB6612 build |
| 12 | **unused** | — | strapping pin: must be LOW at reset (flash voltage) |
| 6-11 | **never** | — | SPI flash (not on the header) |
| 1, 3 | UART0 | USB-serial | programming and debug log |

## Power connections
| From | To |
|---|---|
| Battery + | 3 A fuse → rocker switch → L298N 12V **and** LM2596 IN+ |
| Battery − | L298N GND **and** LM2596 IN− |
| LM2596 OUT+ (5.0 V) | ESP32 VIN **and** L298N 5V terminal |
| LM2596 OUT− | ESP32 GND |
| ESP32 3V3 | IR array VCC, both FC-51 VCC, MPU6050 VCC |
| ESP32 GND | every sensor GND, LED − |

## L298N jumpers
* **Remove ENA and ENB caps**: the ESP32 drives these pins with PWM.
* **Remove the 5V-EN cap**: its regulator is only safe up to 12 V input and the pack gives 16.8 V.
  The L298N logic then takes its 5 V from the LM2596 through the 5V terminal.

## Checks before first power-up (multimeter, ESP32 not plugged in yet)
1. Continuity: battery − to every GND. Battery + reaches the L298N 12V terminal **only** with the switch on.
2. No short between VBAT and GND, 5 V and GND, or 3V3 and GND.
3. Switch on with only the LM2596 connected and turn its pot until OUT reads **5.0 V**.
4. Switch off, plug in the ESP32. Switch on: 3V3 at the IR array VCC pin reads 3.2-3.4 V.
5. With the ESP32 held in reset (EN pressed), the motors do not move.
6. Wheels off the floor for the first motor test. A motor that turns the wrong way: swap its two wires on the L298N.
